# S3 resource interface (version 1)

Packages declare `needs: [{ kind: s3, version: 1, bind_env: { ... } }]`. The installer binds six
environment variables on the consumer containers. External operators and catalog providers must
satisfy the same contract; `keystonectl` verifies bindings with `s3_probe`.

## Parameters

All six are required. Values are strings in the variables named by `bind_env`.

| Parameter | Format | Example |
|---|---|---|
| `endpoint` | `^https?://[A-Za-z0-9.-]+(:[0-9]{1,5})?$` — scheme and host, no path, no trailing `/` | `http://minio:9000`, `https://storage.yandexcloud.net` |
| `region` | `^[a-z0-9-]{1,32}$` | `us-east-1` (MinIO), `ru-central1` (Yandex) |
| `bucket` | `^[a-z0-9][a-z0-9-]{1,61}[a-z0-9]$` — no dots (dots break TLS when using virtual-host style) | `file-mcp` |
| `access_key` | 1–128 non-space characters | |
| `secret_key` | 1–128 non-space characters; secret | |
| `path_style` | `true` or `false` (lowercase) | `true` for MinIO, `false` for AWS |

`http://` is allowed (same Docker network). For a public hostname over HTTP, the probe adds warning
`insecure_endpoint`. Hostnames without a dot (for example `minio-server`) and private IP addresses
are treated as internal and do not trigger that warning.

Environment names used by the probe CLI: `KEYSTONE_S3_ENDPOINT`, `KEYSTONE_S3_REGION`,
`KEYSTONE_S3_BUCKET`, `KEYSTONE_S3_ACCESS_KEY`, `KEYSTONE_S3_SECRET_KEY`, `KEYSTONE_S3_PATH_STYLE`.

## Provider promises

Within the bound bucket, the provider must support:

1. Object operations: `HeadBucket`, `PutObject`, `GetObject`, `HeadObject`, `DeleteObject`,
   `ListObjectsV2` with `Prefix`.
2. Presigned URLs (SigV4 query signing) for `PUT` and `GET` with expiry from 1 second to 7 days
   (604800 s). Links work without extra headers; signed `Content-Type` is the consumer’s
   responsibility.
3. Prefix lifecycle rules: `GetBucketLifecycleConfiguration` / `PutBucketLifecycleConfiguration`
   with `Filter.Prefix` and `Expiration.Days` (integer ≥ 1).

Not part of v1: bucket create/delete, versioning, object lock, ACL, CORS, server-side encryption,
multipart upload via presigned URLs.

## Consumer obligations

Consumers with `needs: s3` must not create buckets; they must honor `path_style` and `region`; link
TTL ≤ 604800 s; when writing lifecycle rules they read existing rules, keep foreign rules, and use
rule IDs prefixed with the package name (for example `file-mcp-uploads`).

## Catalog provider (`kind: resource`)

Why: [ADR 0003](../../adr/0003-resources-as-interfaces.md).

`provides: { kind: s3, version: 1, container: <role> }` with `provision.per_consumer: bucket_and_user`
issues per consumer (package name):

- Bucket named after the consumer.
- IAM user named after the consumer; access key id equals the user name; secret ≥ 32 bytes (generated
  by the installer, passed to the provider).
- Policy allowing only on that bucket:
  `s3:ListBucket`, `s3:GetBucketLocation`, `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject`,
  `s3:GetLifecycleConfiguration`, `s3:PutLifecycleConfiguration`.
- Parameters: `endpoint` = `http://<package>-<provides.container>:<port>` on the resource network
  (MinIO from the catalog: `http://minio-server:9000`), `region: us-east-1`, `path_style: true`.

Re-provisioning the same consumer is idempotent. Provision output must pass `s3_probe` with exit code 0.

## External S3

The operator creates the bucket and keys with the same permissions. Secrets are supplied via
environment variables or mode-`600` files, never on the command line. The installer runs the probe;
exit 0 means the binding is ready; exit 4 means lifecycle is unsupported (installer may ask whether
to continue without lifecycle); other codes fail with a reason.

Example AWS IAM policy (same seven actions on one bucket):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:ListBucket",
        "s3:GetBucketLocation",
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject",
        "s3:GetLifecycleConfiguration",
        "s3:PutLifecycleConfiguration"
      ],
      "Resource": [
        "arn:aws:s3:::file-mcp",
        "arn:aws:s3:::file-mcp/*"
      ]
    }
  ]
}
```

## Provider hints

| Backend | Typical endpoint | Region | path_style |
|---|---|---|---|
| MinIO (catalog) | `http://minio-server:9000` | `us-east-1` | `true` |
| AWS S3 | `https://s3.amazonaws.com` | e.g. `us-east-1` | `false` |
| Yandex Object Storage | `https://storage.yandexcloud.net` | e.g. `ru-central1` | `false` |

Only `s3_probe` is authoritative.

## MinIO provider risk (accepted)

The default `s3/v1` provider in the catalog is the `minio` package. Free MinIO releases are,
to the best of current knowledge, no longer receiving updates (including security fixes) since late
2025. The package runs the last published server and client binaries. Docker Hub no longer serves
that image, so the binaries are packaged for GHCR. This risk is accepted by the product owner.
Pinned release dates and how to check for new releases are documented in the `minio-resource` package.
Other `s3/v1` providers (Garage, SeaweedFS, RustFS) or external S3 use the same interface without
changing services.

## Interface versioning

Behavior that old providers cannot implement, or a breaking change to parameter meaning, requires
`s3/v2`. Clarifications that do not change behavior stay on version 1.

## Probe

Command:

```bash
python -m keystonectl.resources.s3_probe [--params-file FILE] [--endpoint-override URL] \
  [--skip-lifecycle] [--json]
```

Without `--params-file`, parameters come from `KEYSTONE_S3_*`. There are no CLI flags for secrets.
`--endpoint-override` sends all requests and presigned URLs to another base URL (for example a
container IP reachable from the host); the report keeps the configured `endpoint` and sets
`checked_via` to the override.

YAML params files must be mode `600` (not group/other readable).

The probe uses **boto3** (not the MinIO Python SDK) so behavior matches AWS-compatible endpoints.

Steps (first failure stops, except lifecycle and cleanup as noted):

| Step | Action | Check field | Failure → exit, `error.code` |
|---|---|---|---|
| 0 | Validate parameters | — | **2** `missing_parameters` / `invalid_parameters` |
| 1 | `HeadBucket` | `head_bucket` | **1** `auth_failed`, `bucket_not_found`, `wrong_region`; **3** `endpoint_unreachable`, `provider_error` |
| 2 | Presign PUT, HTTP PUT to `keystone-probe/<id>.txt` | `presign_put` | **1** `presign_put_failed`; **3** network/5xx |
| 3 | Presign GET, HTTP GET | `presign_get` | **1** `presign_get_failed`, `presign_get_mismatch`; **3** network/5xx |
| 4 | Read lifecycle, replace only rule `keystone-s3-probe`, write | `lifecycle` | **4** `lifecycle_unsupported` if steps 1–3 OK; **3** network/5xx |
| 5 | Delete probe object | `cleanup` | warning `cleanup_failed` only |

Exit codes: **0** all supported features work; **1** binding invalid (retry won’t help); **2**
missing/invalid parameters; **3** transient/provider (**3** sets `retryable: true`); **4** all except
lifecycle works.

Rule `keystone-s3-probe` (`Prefix: keystone-probe/`, `Expiration.Days: 1`) is left enabled on
purpose: it only affects the probe prefix and expires stray probe objects after one day. Foreign
lifecycle rules are preserved.

Example success JSON:

```json
{
  "ok": true,
  "exit_code": 0,
  "endpoint": "http://minio-server:9000",
  "bucket": "file-mcp",
  "region": "us-east-1",
  "path_style": true,
  "checks": {
    "head_bucket": "ok",
    "presign_put": "ok",
    "presign_get": "ok",
    "lifecycle": "ok",
    "cleanup": "ok"
  },
  "warnings": [],
  "error": null,
  "missing": []
}
```

JSON output, logs, and error messages must not contain `secret_key`, `access_key`, or presigned URL
signatures.
